Jupyter Notebook Best Practices

How to write notebooks that are clear, reproducible, and ready to submit. Good habits now save time later.

Structure & Organization

Start with a title and description

# INFO 4360 — Homework 2: Word Frequency Analysis
# Due: [DATE]
# Name: [YOUR NAME]

## Overview
This notebook loads movie reviews, tokenizes them, removes stopwords,
and analyzes word frequency to identify the most common words in
positive vs. negative reviews.

Use markdown headers to organize sections

## 1. Load the Data
## 2. Preprocess and Tokenize
## 3. Count Word Frequencies
## 4. Visualize Results
## 5. Discussion & Conclusions

This makes it easy for readers (including you, weeks later) to navigate the notebook.

Code Quality

Use descriptive variable names

✓ Good

positive_reviews = [r for r in data
                   if r['label'] == 1]
review_tokens = word_tokenize(reviews)

✗ Avoid

x = [r for r in data if r['label'] == 1]
y = word_tokenize(x)

Add comments explaining the why, not the what

✓ Good

# Remove stopwords to focus on
# meaningful content words
tokens = [t for t in tokens
         if t not in stopwords]

✗ Avoid

# Loop through tokens
for t in tokens:
    # Check if in stopwords
    if t not in stopwords:
        # Keep it
        filtered.append(t)

Keep cells focused

  • One idea per cell: Setup, load data, clean data, analyze, visualize
  • Not too long: If a cell is 40+ lines, consider breaking it up
  • Run cells in order: A reader should be able to run from top to bottom without errors

Output & Readability

Display results clearly

✓ Good

print(f"Total positive reviews: {len(positive)}")
print(f"Total negative reviews: {len(negative)}")
print(f"\nTop 10 words:")
print(top_10_words)

✗ Avoid

result
some_variable
x

← Cryptic. Readers don't know what they're looking at.

Remove extra output

  • Don't output test code or exploratory print statements
  • If a cell produces 100 lines of output, use .head() or limit results
  • Clear output that won't help graders understand your work
# Before submission: limit output
word_freq.most_common(10)  # Show only top 10, not all 5000

Reproducibility

Use relative paths (never hardcoded paths)

✓ Good

# Data is in the same folder
df = pd.read_csv("data.csv")

✗ Avoid

# Only works on YOUR computer
df = pd.read_csv(
  "C:\\Users\\Tianjie\\Dropbox\\...\\data.csv"
)

Specify versions (when it matters)

import nltk
import pandas as pd

print(f"NLTK version: {nltk.__version__}")
print(f"Pandas version: {pd.__version__}")

Don't rely on undefined variables

# ✗ Bad: Assumes 'data' exists from a previous cell
tokens = word_tokenize(data)

# ✓ Good: Either load it or assume it's been loaded above
data = load_dataset("imdb")
tokens = word_tokenize(data['train'][0])

Before Submission

Run the entire notebook from scratch

  1. Go to **Kernel → Restart & Run All**
  2. Fix any errors
  3. Make sure outputs display correctly

This catches bugs where cells depend on undefined variables or out-of-order execution.

Clean up before submission

  • Remove scratch cells or exploratory code
  • Keep AI use log visible (usually at the top or bottom)
  • Double-check filenames: INFO4360_Homework2_YourName.ipynb

Verify the output looks good

  • No error messages or tracebacks
  • Plots and tables are readable
  • Text is clear and well-organized
Pro tip: Imagine grading this notebook on a different computer. Would it run without errors? Would the output be clear? If yes, you're good to submit.

Common Mistakes to Avoid

Mistake Why it's a problem
Cells that don't run in order Grader has to jump around to make your code work
100+ lines in one cell Hard to follow logic; hard to debug if something breaks
No markdown explanation Code alone doesn't show your thinking
Hardcoded file paths Breaks on anyone else's computer
No output or output is hidden Grader can't see if your code works
Comments that just restate code # x = 5 doesn't need a comment; # Store the threshold as 5 does

Summary Checklist

  • ☐ Notebook has a title and overview at the top
  • ☐ Code is organized into logical sections with markdown headers
  • ☐ Variable names are descriptive
  • ☐ Comments explain the why, not just the what
  • ☐ Each cell focuses on one idea
  • ☐ Output is clear and readable
  • ☐ File paths are relative (not hardcoded)
  • ☐ Notebook runs top-to-bottom without errors
  • ☐ AI use log is included (if you used AI)
  • ☐ Filename follows the format: INFO4360_HW#_YourName.ipynb
