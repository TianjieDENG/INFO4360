GitHub Setup for the Group Project

Create your project repository and make your first commit. This is due as part of Phase 1: every group member needs at least one commit in the repo before the proposal deadline.

Nearly every analytics team uses git — learning it now is an investment that pays off immediately, not just by the time you're job hunting. Git is worth the setup cost: it lets you undo a mistake instead of panicking, your commit history documents how your analysis evolved (handy when you're writing up findings later), and a teammate or grader can reproduce your exact code. Once you're pushing to GitHub, it becomes something else too: a public record of your work.

Why your own GitHub, not a course account: this repo lives under your personal GitHub account, not a class organization. That's deliberate — by the end of the term it should be something you'd link on a resume or portfolio, and it stays yours after the course ends.

Before You Start

This guide assumes you've already completed the main Environment Setup guide, which covers:

  • A GitHub account (Step 4)
  • Git installed, with your name and email configured (Step 5)
  • VS Code, which has Git support built in

If any of those are missing, go do that first, then come back here.

Step 1: Create the Repository on GitHub

  1. Go to github.com and sign in.
  2. Click the + icon in the top-right corner, then New repository.
  3. Name it something clear, for example info4360-project-yourteamname.
  4. Leave visibility set to Public. This is what makes it a portfolio piece. (You can switch it to private later if you ever need to — Settings → General → Danger Zone → Change visibility.)
  5. Check Add a README file.
  6. Under Add .gitignore, select the Python template.
  7. Click Create repository.
Why now, before you have anything to hide: later in the term you'll get a Claude API key for the project. A .gitignore file tells git which files to never track — the Python template already covers .env files, cache folders, and virtual environments. Your repo is public, so a key committed by accident is exposed to anyone. Setting this up now, before any key exists, means you'll never have the chance to forget.

Step 2: Add Your Teammate as a Collaborator

Skip this step if you're working solo.

  1. On your new repo's page, click Settings.
  2. In the left sidebar, click Collaborators.
  3. Click Add people, and enter your teammate's GitHub username or the email tied to their account.
  4. Your teammate needs to accept the invite — check email or the notification bell on GitHub.
Only one of you created this repo — that's fine, but it matters how you commit. GitHub attributes each commit to whoever authored it, not to whoever owns the repo. So if the teammate who didn't create the repo clones it and pushes commits under their own GitHub account (using their own git config user.name/user.email from Environment Setup, Step 5), those commits show up on their contribution graph, in the repo's Contributors list, and they can pin this repo to their own profile — all regardless of who owns it. If one person does all the committing for both of you, only that person gets any of that credit. Both of you need to each clone the repo and commit from your own machine and account for this to work.

Step 3: Create a Local Folder (Not in Dropbox)

This is a general-purpose folder where your git repos will live for the rest of the term — you're setting it up once, not per project. Before cloning, create it somewhere outside Dropbox (or OneDrive, Google Drive, etc.). Git and Python virtual environments don't play nice with cloud-sync folders — syncing can lock files mid-write or create duplicate/conflicted copies of your .git history.

Open a terminal and run:

Windows (PowerShell)

mkdir C:\Users\YourName\repos

Mac (Terminal)

mkdir ~/repos

You can also create this folder by hand in File Explorer (Finder on Mac) instead of typing a command — just remember where you put it, since you'll need the path in the next step. Pick any location outside Dropbox; the paths above are just examples.

Step 4: Clone the Repository into Your Repos Folder

Cloning downloads a copy of the repo — connected to GitHub — into the folder you just made. From here on, you'll write and edit your project in VS Code and push your changes back to GitHub from that same folder; this step is what connects the two.

  1. On the repo's GitHub page, click the green Code button and copy the HTTPS URL.
  2. Open VS Code. Open the Command Palette (Ctrl+Shift+P on Windows, ⌘⇧P on Mac).
  3. Type and select Git: Clone.
  4. Paste the URL you copied, then press Enter.
  5. Choose the repos folder you just created.
  6. When VS Code asks, click Open to open the cloned folder.

The first time you do this, VS Code may open a browser window asking you to sign in to GitHub — follow that prompt.

Prefer the command line?

Open a terminal (in VS Code: Terminal → New Terminal) and run:

Windows (PowerShell)

cd C:\Users\YourName\repos
git clone https://github.com/yourusername/your-repo-name.git
cd your-repo-name

Mac (Terminal)

cd ~/repos
git clone https://github.com/yourusername/your-repo-name.git
cd your-repo-name

Then use File → Open Folder in VS Code to open that folder.

Step 5: Make Your First Commit

  1. Open README.md in VS Code and add a sentence or two describing your project (a placeholder is fine for now — you'll fill it in as you go).
  2. Save the file (Ctrl+S or ⌘S).
  3. Open the Source Control panel — the branching icon in the left sidebar, or Ctrl+Shift+G (⌘⇧G on Mac).
  4. You'll see README.md listed under Changes. Hover over it and click the + to stage it.
  5. Type a short, clear commit message in the box at the top, for example Add initial README with project description.
  6. Click the checkmark button (or Commit) above the message box.
  7. Click Sync Changes to push your commit to GitHub.

Prefer the command line?

# Check what changed
git status

# Stage your changes
git add .

# Commit with a message
git commit -m "Add initial README with project description"

# Push to GitHub
git push origin main

Step 6: Verify

  1. Go back to your repository's page on github.com and refresh.
  2. You should see your commit message and a commit count greater than the automatic "Initial commit."
  3. If you're on a team, the other teammate must complete the steps in the section below on their own machine, so everyone shows up in the repo's contributor history.
You're set up. From here on, you'll repeat the edit → stage → commit → push cycle every time you work — see Everyday Git Workflow for that ongoing loop, including how to handle pushing alongside a teammate.

If You're the Teammate Who Didn't Create the Repo

You don't create a second repo. Work in the one your teammate made.

  1. Accept the invite from Step 2 (check email or the GitHub notification bell). Pushing won't work until you do.
  2. Create your repos folder on your own machine, using Step 3.
  3. Clone the owner's repo using Step 4, with the HTTPS URL from your teammate's repo page, not one you create.
  4. Check your git identity is your own name and email from your GitHub account. Run git config user.name and git config user.email in the terminal to see them. This is what credits your commits to you.
  5. Make a real first commit on your machine using Step 5, such as adding a line to the README. Don't just watch your teammate push.
  6. Check the Contributors list on the repo's GitHub page. Your name should be there with your commits.

Common Issues

"Repository not found" or "Permission denied" when cloning

Either the repo is private and you haven't been added as a collaborator yet, or VS Code is signed in with the wrong GitHub account. Check Step 2, or sign out and back in from the Accounts icon in VS Code's bottom-left corner.

Nothing shows up in Source Control

Make sure you saved the file after editing it. Unsaved changes don't appear as changes to commit.

"Push rejected" when clicking Sync Changes

Someone else — your teammate — pushed a commit first. Click Sync Changes again; VS Code will pull their changes and merge before pushing yours.

Asked to sign in when pushing

Normal the first time. Follow the browser window that opens and authorize VS Code to access your GitHub account.

Reminder: commit messages should say what changed, not just "update" or "fix." For example, Add initial README with project description is useful; update is not. Your project spec (posted separately) has more examples.
