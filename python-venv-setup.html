Python Virtual Environments

About 20–30 minutes

Isolate packages for your course work. Learn how virtual environments work and how to set one up for INFO 4360. The toggle above switches every instruction between Windows and Mac — pick your laptop and read straight through.

Why This Matters

Before you write any code, your Python environment needs to be set up correctly. Without this, you'll hit mysterious errors where "I installed the package but Python can't find it" — and debugging that takes hours.

A virtual environment is a clean, isolated space for your course work. It prevents version conflicts, keeps your system Python untouched, and makes your project reproducible.

The Multiple Python Problem

Many students have installed Python several times — once from python.org, maybe once from Anaconda, perhaps one came with their IDE. Each installation has its own separate location on disk with its own site-packages folder where packages live.

💡 What is site-packages?

site-packages is a folder inside each Python installation. When you run pip install nltk, the package lands in that Python's site-packages. When your code runs import nltk, Python searches its site-packages folders to find it.

When multiple Pythons are on your machine, you need to know which one you're using. A virtual environment solves this by creating one clean Python environment for this course.

  1. Create a virtual environment

    Required ~5 min

    Venvs are thousands of small files that change constantly. Don't put it in Dropbox — it will try to sync all of them, which is slow and can corrupt the venv. Create it in a plain system folder.

    Open PowerShell and run:

    mkdir C:\Users\YourName\venvs
py -m venv C:\Users\YourName\venvs\info4360

    Replace YourName with your actual username. This creates a fresh Python environment at that path. It takes a few seconds and produces no output — that's normal.

    Open Terminal and run:

    python3 -m venv ~/info4360-venv

    This creates a fresh Python environment in your home directory. It takes a few seconds and produces no output — that's normal.

  2. Activate the virtual environment

    Required ~2 min

    First, enable PowerShell script execution (one time only):

    Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

    Type Y and Enter if it asks. This allows scripts you created locally to run.

    Then, activate the venv:

    C:\Users\YourName\venvs\info4360\Scripts\Activate.ps1

    Your prompt should now start with (info4360). That prefix means the venv is active.

    source ~/info4360-venv/bin/activate

    Your prompt should now start with (info4360-venv). That prefix means the venv is active.

    💡 Stay activated: Keep the venv active for all the steps below. Don't type deactivate yet! All the commands below (pip install, etc.) must run while the venv is active.

  3. Install packages

    Required ~3 min

    With the venv active (you should see (info4360) in your prompt), install the course packages:

    pip install nltk matplotlib datasets ipykernel numpy

    You'll see download and build progress. It takes a minute or two. At the end, you should see Successfully installed ....

    Verify:

    pip list

    You should see nltk, matplotlib, datasets, and others listed.

    Optional: See where packages live

    Open File Explorer and navigate to:

    C:\Users\YourName\venvs\info4360\Lib\site-packages

    You'll see folders like nltk/, matplotlib/, datasets/, and many others. These are your installed packages and their dependencies — all isolated to this venv.

    Open Finder and navigate to:

    ~/info4360-venv/lib/python3.*/site-packages

    You'll see folders for your installed packages and their dependencies — all isolated to this venv.

  4. Connect to VS Code

    Required ~5 min

    Tell VS Code to use your venv for all Python work.

    Step 1: Select the interpreter

    Press Ctrl+Shift+P (or Cmd+Shift+P on Mac) and type Python: Select Interpreter.

    You'll see a few options. Click "Enter interpreter path".

    Paste this path (replace YourName with your username):

    C:\Users\YourName\venvs\info4360\Scripts\python.exe

    Paste this path:

    ~/info4360-venv/bin/python

    Press Enter. VS Code will add this venv to your interpreter list.

    Step 2: Set the kernel in your notebook

    Important: Selecting the interpreter above does NOT automatically change the notebook kernel. You need to set the kernel separately for each notebook.

    1. Open a notebook (e.g., Class 2's notebook).
    2. Top-right corner of the notebook, click the kernel selector (shows "Select Kernel" or a Python version).
    3. Click "Select Another Kernel" to see more options.
    4. Click "Python Environments" to see available interpreters.
    5. Look for and select info4360 or your venv path. Click it.
    Quick tip: VS Code remembers your kernel choice per notebook file. You only set it once for each notebook. When you create a new notebook, it's just 2 clicks: "Select Another Kernel" → "Python Environments" → your venv.

  5. Save your requirements (Optional)

    Optional ~3 min

    Why this matters: A requirements.txt file lists exactly what packages and versions you installed. This is crucial for:

    • Reproducibility: Recreate the exact environment later if you delete the venv.
    • Collaboration: Teammates can install the same packages. Everyone has the same environment.
    • Submission: Graders see what you used.

    Step 1: Navigate to your course work folder (venv still active)

    Change your directory to where you keep your course files:

    (info4360) PS C:\WINDOWS\System32> cd "C:\Users\YourName\info4360"

    After running this, your prompt should show your course folder. The (info4360) prefix stays.

    (info4360-venv) ~ % cd ~/info4360

    Step 2: Save the requirements (venv still active)

    (info4360) PS C:\Users\YourName\info4360> pip freeze | Out-File -Encoding utf8 requirements.txt
    (info4360-venv) ~/info4360 % pip freeze > requirements.txt

    Step 3: Verify it worked

    Open File Explorer (Windows) or Finder (Mac) and navigate to your course folder. Look for requirements.txt. Open it in a text editor and verify you see a list of packages like:

    nltk==3.8.1
matplotlib==3.7.1
datasets==2.14.0
ipykernel==6.25.0
numpy==1.24.3
...
    💡 Where to put it: Keep requirements.txt with your course files, not inside the venv folder. The venv can be deleted and recreated; requirements.txt stays with your code.

  6. Install more packages later

    Reference ~2 min per install

    During the course, you may need to install additional packages for assignments. The process is the same every time:

    Step 1: Activate the venv

    C:\Users\YourName\venvs\info4360\Scripts\Activate.ps1

    Or use the VS Code terminal — it may auto-activate if you set the interpreter in Step 4.

    source ~/info4360-venv/bin/activate

    Step 2: Install the package

    With the venv active, run pip install with the package name:

    pip install scikit-learn pandas transformers

    Step 3: Update requirements.txt

    cd "C:\Users\YourName\info4360"
pip freeze | Out-File -Encoding utf8 requirements.txt
    cd ~/info4360
pip freeze > requirements.txt
    ⚠️ Always activate first: Before any pip install, make sure your prompt shows (info4360) or (info4360-venv). Otherwise the package goes into your system Python, not the venv.

Troubleshooting

PowerShell won't navigate to your folder (Windows)

Cause: Your folder path has spaces in it (like "INFO4360 Fall 2026").

Fix: Wrap the path in quotes:

cd "C:\Users\YourName\Dropbox\Work\Teach\INFO4360 Fall 2026"

"python: The term is not recognized"

Cause: The venv isn't active.

Fix: Check that your prompt starts with (info4360) or (info4360-venv). If not, run the activation script again.

"ModuleNotFoundError: No module named 'nltk'"

Cause: The package is installed in one Python, but your notebook is using a different Python.

Fix:

  1. In a terminal with the venv active, run python -c "import sys; print(sys.executable)" to see which Python you're using.
  2. In your notebook, run the same command in a cell to see which Python the notebook is using.
  3. If they don't match, re-select the kernel in the notebook.

Best Practices

  • Always activate before installing: Check the prompt starts with (info4360) before pip install.
  • Keep requirements.txt updated: After installing new packages, update it.
  • Don't put the venv in Dropbox: It will sync constantly and cause issues.
