Python Virtual Environments

Isolate packages for your course work. Learn how PATH works, why you need a virtual environment, and how to set one up for INFO 4360.

Why This Matters

Before you write any code, your Python environment needs to be set up correctly. Without this, you'll hit mysterious errors where "I installed the package but Python can't find it" — and debugging that takes hours.

A virtual environment is a clean, isolated space for your course work. It prevents version conflicts, keeps your system Python untouched, and makes your project reproducible.

Part 1: Understanding the Problem

The Multiple Python Problem

Many students have installed Python several times — once from python.org, maybe once from Anaconda, perhaps one came with their IDE. Each installation has its own separate location on disk with its own site-packages folder where packages live.

💡 What is site-packages?

site-packages is a folder inside each Python installation. When you run pip install nltk, the package lands in that Python's site-packages. When your code runs import nltk, Python searches its site-packages folders to find it.

When multiple Pythons are on your machine, you need to know which one you're using. Here's what happens when you don't:

❌ Without clarity

You install a package in Terminal (Python 3.11).

Your notebook kernel is Python 3.14.

The notebook says ModuleNotFoundError.

You reinstall. Still doesn't work. You're stuck.

✓ With a virtual environment

You create one clean Python environment for this course.

Terminal uses it. Notebook uses it.

Everything is synchronized.

No confusion.

What is PATH?

When you type python in the terminal, Windows searches a list called PATH to find which python.exe to run. It searches left-to-right and stops at the first match. If you have three Pythons and the wrong one is first on the list, you're using it by accident.

# This is what your PATH might look like:
C:\Python311\
C:\Python312\
C:\Python314\
C:\Program Files\Git\cmd
...

When you type python, Windows checks each folder in order. Python 3.11 is first, so python means Python 3.11 — even if you wanted 3.14.

🔍 See your PATH

In PowerShell, type:

$env:PATH -split ';' | Select-String Python

This shows only the Python-related entries, in search order. The first one wins when you type python.

Why a Virtual Environment Solves This

A virtual environment (venv) is a folder containing its own Python and its own site-packages. When you activate it, it prepends itself to PATH, so it wins the search. Now:

  • Your course code lives in one venv
  • All packages go into that venv's site-packages
  • When you activate it, python and pip mean this venv — unambiguous
  • The rest of your system Python stays untouched
  • If you later install a conflicting version of something for another project, it doesn't affect this course

Part 2: Setting Up Your Virtual Environment

Step 1: Create a folder (not in Dropbox)

Venvs are thousands of small files that change constantly. Dropbox tries to sync all of them, which is slow and can corrupt the venv. Create your venv outside Dropbox.

Open PowerShell and run:

mkdir C:\Users\YourName\venvs

Replace YourName with your actual username.

⚠️ Not in Dropbox

Do NOT put the venv in C:\Users\YourName\Dropbox\.... It will constantly sync and cause issues. Always put venvs in a plain system folder.

Step 2: Create the virtual environment

In PowerShell (or VS Code terminal):

py -m venv C:\Users\YourName\venvs\info4360

Replace YourName with your username. This creates a fresh Python environment at that path. It takes a few seconds and produces no output — that's normal.

ℹ️ Why use py -m venv?

py is the Python Launcher — it avoids PATH guessing and reliably finds the Python you installed. The -m venv flag tells it to run the venv module (which comes built-in).

Step 3: Enable PowerShell script execution (one time only)

By default, PowerShell blocks scripts for security. The venv's activation script needs to run once. Do this:

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

Type Y and Enter if it asks. This allows scripts you created locally to run, while still blocking unsigned scripts from the internet. You only do this once per machine.

Step 4: Activate the virtual environment

Run:

C:\Users\YourName\venvs\info4360\Scripts\Activate.ps1

Your prompt should now start with (info4360). That prefix means the venv is active. Everything you install from here goes into this venv.

# Before activation:
PS C:\Users\YourName\Dropbox\Work\Teach\INFO4360 Fall 2026>

# After activation:
(info4360) PS C:\Users\YourName\Dropbox\Work\Teach\INFO4360 Fall 2026>

Step 5: Upgrade pip (optional)

Pip is the package installer. Upgrading it first removes noisy warnings:

python -m pip install --upgrade pip

Part 3: Installing Packages for INFO 4360

What you need

Package What it does
nltk Natural Language Toolkit — tokenization, stopwords, word frequency
matplotlib Plotting and visualization
datasets Hugging Face datasets library (for IMDB, etc.)

Install them

With the venv active, run:

pip install nltk matplotlib datasets ipykernel numpy

You'll see download and build progress. It takes a minute or two. At the end, you should see Successfully installed ....

Verify the installation

Check what's installed:

pip list

You should see nltk, matplotlib, datasets, and their dependencies listed.

Part 4: Connecting the Notebook to the Venv

Set the interpreter in VS Code

Press Ctrl+Shift+P and type Python: Select Interpreter.

Pick the one from your venv: It will show something like ./venvs/info4360/bin/python or just (info4360). Select it.

This tells VS Code to use this venv for all Python work in this folder. Any new terminal VS Code opens will auto-activate this venv.

Set the kernel in your notebook

  1. Open a notebook (e.g., Class 2's notebook).
  2. Top-right corner, click the kernel selector (shows "Select Kernel" or a Python version).
  3. Choose "Python Environments" → select the info4360 venv.

Now when you run cells, they use the venv's Python and can import the packages you installed.

Part 5: Save Your Requirements

If you need to recreate this environment later, save a list of what you installed:

pip freeze | Out-File -Encoding utf8 requirements.txt

This creates a requirements.txt file in your course folder listing every package and exact version. To rebuild the venv later:

py -m venv C:\Users\YourName\venvs\info4360-new
C:\Users\YourName\venvs\info4360-new\Scripts\Activate.ps1
pip install -r requirements.txt
📝 Note

The requirements.txt file is safe to keep in Dropbox — it's a single small text file, not thousands of package files.

Troubleshooting

"python: The term 'python' is not recognized"

Cause: The venv isn't active, and Python isn't on PATH.

Fix: Check that your prompt starts with (info4360). If not, run the activate script again.

"ModuleNotFoundError: No module named 'nltk'"

Cause: The package is installed in one Python, but the notebook is using a different Python.

Fix:

  1. In a terminal, with the venv active, run python -c "import sys; print(sys.executable)" to see which Python you're using.
  2. In the notebook, run the same command in a cell to see which Python the notebook is using.
  3. If they don't match, re-select the kernel in the notebook.

Best Practices

  • Always activate before installing: Before pip install, check the prompt starts with (info4360).
  • Use the terminal, not notebook cells: Install packages once in the terminal, not in notebook cells every time.
  • Keep requirements.txt updated: After installing new packages, run pip freeze | Out-File -Encoding utf8 requirements.txt again.
  • Deactivate when done: Type deactivate to leave the venv. You can always reactivate it later.
