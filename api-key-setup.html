Claude API Key Setup

About 10 minutes

Put your Claude API key in a .env file, then run one test cell to confirm your notebooks can reach Claude. Do this once before the first class that uses the API. The toggle above switches the instructions between Windows and Mac.

How the pieces fit

Your notebook never contains the key itself. Instead:

  1. The key lives in a small text file named .env, sitting in the same folder as your notebooks.
  2. At the top of each notebook, load_dotenv() reads that file and puts the key into the notebook's environment.
  3. anthropic.Anthropic() finds the key there automatically.

This way you can share, submit, or push a notebook to GitHub without giving your key away.

Your key is a password, and it spends money.

Everyone in the class shares one spending budget. Anyone who gets your key can run calls against that budget. Never paste the key into a notebook cell, a chat message, a Teams post, or an AI assistant. If you think your key has leaked, email the instructor right away so it can be disabled.

  1. Find your key

    Required~1 min

    Your key came by email from the instructor. It is one long string that starts with sk-ant-, something like:

    sk-ant-api03-Xy7...about 100 characters...AA

    Leave the email open. You will copy the key from it in Step 3. When you copy, make sure you get the whole string, from sk-ant- to the last character, with no space before or after it.

  2. Install the two packages

    Required~2 min

    You need anthropic (talks to Claude) and python-dotenv (reads the .env file). Install them into your course virtual environment, the same one you set up in Python Virtual Environments.

    The simplest way: open any notebook in VS Code, check that the kernel in the top-right corner is your info4360 venv, and run this in a cell:

    %pip install anthropic python-dotenv

    When it finishes, click Restart in the notebook toolbar so the kernel picks up the new packages. You only do this once per venv.

    Why %pip in a cell?

    %pip installs into whatever Python the notebook's kernel is using, so the package always lands in the right place. If you'd rather use the terminal, activate the venv first and run pip install anthropic python-dotenv.

  3. Create the .env file

    Required~3 min

    Where it goes

    Put .env in the folder that holds your course notebooks. If you keep each class in its own subfolder, put .env in the top course folder: load_dotenv() starts in the notebook's own folder and then checks each folder above it, so one file covers every class.

    INFO4360/                  <- .env goes here
├── .env
├── Class 10/
│   └── CDA_Class10_LLMAnalyst.ipynb
└── Class 13/
    └── CDA_Class13_ClaudeTag.ipynb

    Create it in VS Code

    Create it in VS Code, not Notepad. Notepad quietly saves the file as .env.txt, and Windows hides the .txt part, so the file looks right but load_dotenv() can't find it.

    Create it in VS Code, not TextEdit. TextEdit can save it as .env.rtf or add formatting that breaks the file. Also, Finder hides any file whose name starts with a dot, so you won't see .env there unless you press Cmd+Shift+. (period). VS Code's Explorer always shows it.

    1. In VS Code, open your course folder: File → Open Folder…
    2. In the Explorer panel on the left, hover over the folder name at the top and click the New File icon (a page with a +).
    3. Type the name exactly .env (dot, then env, nothing else) and press Enter. The empty file opens in the editor.
    4. Type this line, then paste your key right after the =: 
      ANTHROPIC_API_KEY=
      The finished file is one line that looks like: 
      ANTHROPIC_API_KEY=sk-ant-api03-Xy7...AA
    5. Save: Ctrl+SCmd+S. The dot on the file's tab turns into an ×.
    Format rules
    • The name is exactly ANTHROPIC_API_KEY, all capitals, with underscores.
    • No spaces around the =.
    • No quotation marks around the key.
    • The key alone, without ANTHROPIC_API_KEY= in front, does not work.

  4. Keep .env out of GitHub

    Required~1 min

    If your course folder is a Git repository (your group project repo is), Git must ignore .env. The Python .gitignore template already lists it. To check:

    1. Open the Source Control panel in VS Code (the branching icon on the left).
    2. Look at the list of changed files. .env should not be there.
    3. In the Explorer, .env should appear in gray. Gray means Git is ignoring it.

    If .env does show up as a change, don't commit. Add a line .env to your .gitignore first. See Understanding Your .gitignore.

    If your notebooks folder is not a Git repository, there is nothing to do here.

  5. Run the test block

    Required~2 min

    The test code is below. You can run it in a notebook (Option A) or from the terminal (Option B). Both give the same result, so pick one.

    Option A: in a notebook

    1. Create a new notebook in the same folder as .env (or in a class subfolder below it). Call it api_test.ipynb.
    2. Select your info4360 venv as the kernel (top-right corner).
    3. Paste the test code into the first cell and run it.

    Option B: from the terminal

    1. In VS Code's Explorer, create a new file in the same folder as .env named api_test.py. Paste the test code into it and save.
    2. Open a terminal: Terminal → New Terminal. It opens in your course folder.
    3. Activate your venv, if the prompt doesn't already start with (info4360): 
      C:\Users\YourName\venvs\info4360\Scripts\Activate.ps1
      source ~/venvs/info4360/bin/activate
    4. Run the script: 
      python api_test.py
      If the terminal says it can't find api_test.py, it's in a different folder. Move to the folder that holds the script with cd "path\to\that folder" (quotes needed if the path has spaces) and run it again.

    Like the notebook, the script finds .env by looking in its own folder and the folders above it.

    The test code

    import os
import anthropic
from dotenv import load_dotenv

# 1. Read the .env file
found = load_dotenv()
print(".env file found:", found)
if not found:
    print("   Running in:", os.getcwd())

# 2. Check that the key is in the environment
api_key = os.getenv("ANTHROPIC_API_KEY")
if not api_key:
    raise RuntimeError("No ANTHROPIC_API_KEY found. Check the .env file (Step 3), then run "
                       "this again (in a notebook, restart the kernel first).")
print("Key loaded (ends in ..." + api_key[-4:] + ")")

# 3. Make one small call to Claude
client = anthropic.Anthropic()
try:
    response = client.messages.create(
        model="claude-haiku-5-5",
        max_tokens=1024,
        output_config={"effort": "low"},
        messages=[{"role": "user", "content": "Reply with exactly: API key works."}],
    )
except anthropic.AuthenticationError:
    raise RuntimeError("Claude rejected the key. Re-copy it from the email into .env, save, "
                       "and run this again (in a notebook, restart the kernel first).") from None

# The reply is in the text block (a thinking block may come before it)
reply = next(b.text for b in response.content if b.type == "text")
print("Claude says:", reply)
print("Tokens used:", response.usage.input_tokens, "in,", response.usage.output_tokens, "out")

    You should see something like

    .env file found: True
Key loaded (ends in ...x9AA)
Claude says: API key works.
Tokens used: 20 in, 6 out

    Your last four characters and token counts will differ. If you see Claude says: followed by a reply, you're set. This test costs a small fraction of a cent.

    What each part checks

    Part 1 checks that Python can find .env. Part 2 checks that the line inside it is written correctly. Part 3 checks that Claude accepts the key. The first part that fails tells you where to look; match the message to the troubleshooting list below.

Troubleshooting

.env file found: False

Cause: the file isn't in this notebook's folder or any folder above it, or it was saved under a different name.

Fix: compare the folder printed after Running in: with where your .env is. In the terminal, also check that api_test.py sits in the same folder as .env (or below it).

If you made the file outside VS Code, it may be named .env.txt. In File Explorer, click View → Show → File name extensions to see the full name, then rename it to .env. Or delete it and recreate it in VS Code (Step 3).

If you made the file outside VS Code, it may be named .env.txt or .env.rtf. In VS Code's Explorer, right-click it → Rename and change it to .env. Or delete it and recreate it in VS Code (Step 3).

RuntimeError: No ANTHROPIC_API_KEY found

Cause: the file was found but the line inside is wrong, or the file wasn't saved.

Fix: open .env and check the line against the format rules in Step 3 (spelling, capitals, no spaces, no quotes). Save, then run the test again. In a notebook, click Restart in the toolbar first.

Claude rejected the key

Cause: the key in .env isn't complete, has an extra character, or has been disabled.

Fix: copy the key from the email again, replace everything after the =, save, and rerun (restart the kernel first if you're in a notebook). If it still fails, email the instructor.

ModuleNotFoundError: No module named 'dotenv' (or 'anthropic')

Cause: the package isn't installed in the Python this notebook is using.

Fix: in a notebook, check the kernel in the top-right corner is your info4360 venv. In the terminal, check the prompt starts with (info4360). Then redo Step 2. Note the names differ: you install python-dotenv but import dotenv.

I fixed .env but the notebook still uses the old key

Cause: load_dotenv() does not replace a key already loaded in the running kernel.

Fix: click Restart in the notebook toolbar, then run the cells again. Any time you edit .env, restart.

An error mentioning a spend limit, credit, or usage limit

Cause: the class budget has run out. Your key and setup are fine.

Fix: let the instructor know. Don't create a personal account to work around it.

After the test works

  • Every class notebook that uses Claude starts with the same load_dotenv() setup cell. As long as the notebook sits in or below the folder with .env, it will just work.
  • You can delete api_test.ipynb or api_test.py, or keep it for checking your setup later.
  • Your key is for in-class code and homework API calls only. It is not for Claude Code or other tools.
